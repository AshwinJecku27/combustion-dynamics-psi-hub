# Evidence store v1.1: what is here, and what can be verified

## The situation
The SI release candidate was built from an **evidence store v1.1** (`si-evidence/`), whose declared SHA-256 is
`a77e55486a4d25f0c284c3467b485f9cc3aeded142a285a9e346357870aed548`. **The store files were not supplied** with
`si-release-candidate.zip`, and neither was the script that turned them into the Worker bundle
(`scripts/build_bundle.py`). This repository therefore contains:

| Present | Not present |
|---|---|
| `si/worker/src/bundle.js`: a GENERATED, reduced copy of the store (header: "GENERATED by scripts/build_bundle.py from si-evidence store v1.1. Do not edit"). It holds 6 investigation summaries with statistics, 34 report passages, 23 limitations, 22 comparison rules, identifier groups, 10 precomputed calculations, full records for PSI-98 (4) and PSI-99 (24), and the ids of all 797 records. | The store record files (by the calculation `method` fields, `store/records/<PSI-ID>.jsonl`), `investigations.json`, `partial_gravity_scan.json` and the other store files |
| The release manifest entry for the bundle (`si-release/SHA256SUMS.txt`) | Whatever file or file set the hash `a77e5548…` was computed over |
| The frozen v1 dashboard arrays (`src/data.js`, `src/data2.js`): an earlier, separate derivation from the same NASA PSI files | The NASA PSI source CSVs, PDFs, DoD documents (see `data/README.md`) |

**The bundle is not equivalent to the store.** It omits the record-level field values of PSI-10, PSI-159, PSI-69
and PSI-101, so the store cannot be rebuilt from it. The original store was **not** regenerated, reconstructed or
substituted here; `bundle.js` is byte-identical to the release candidate's.

## What `verify_embedded.mjs` checks
`node si/evidence/verify_embedded.mjs` (results in `VERIFICATION_RESULTS.md`; also run by CI) checks:
1. **Integrity:** the bundle's bytes match the release manifest, and the bundle and dashboard both declare store v1.1 / `a77e5548…`.
2. **Internal consistency:** all 23 limitations are present; every referenced limitation and cited record id exists; ids are unique; the count calculations equal the id lists and statistics; no investigation claims partial-gravity data.
3. **Agreement with the v1 derivation:**
   - record-id sets for PSI-10 (147 steady rows plus 60 ramped, LIM-003), PSI-159, PSI-69 and PSI-101;
   - the FLEX O2 > 0.30 (9) and O2 = 0.30 (15) calculations, recomputed from the v1 O2 column;
   - the SAME-R material x primary/aged breakdown, recomputed;
   - all 9 SAFFIRE-II samples field by field (141 of 153 fields identical; the other 12 are missing values, written `null` in v1 and `"n/a"` or `""` in the store);
   - the SAFFIRE-I burn times and flow directions.
4. **Qualifications kept:**
   - LIM-008: the PSI-98 thickness stays raw `"0.37"` with its unit flagged as disputed, and is not converted.
   - LIM-009: the SAFFIRE-II CSV and DoD thickness and flow mismatches stay flagged and unresolved.
   - LIM-012: the FLEX "CO" column stays undefined.

Current result: PASS 26, DIFF 1 (the missing-value representation above), FAIL 0, NOT VERIFIABLE 4.

## What this does NOT establish
- **The store hash.** `a77e5548…` cannot be recomputed without the store files. It is a value the release *declares*.
- **Correctness against NASA data.** Agreement between the bundle and the v1 arrays shows that two derivations made in this project are consistent. Both come from the same NASA files, which are not in the repository. Neither has been checked against those files here.
- **Report passages.** The 34 quotes and page numbers cannot be checked without the PDFs.
- **Record field values for PSI-10, PSI-159, PSI-69 and PSI-101.** These are not embedded, so they cannot be compared.

## To close the gap
Supply the original `si-evidence/` folder and its checksum file from the session that built the release, along
with `scripts/build_bundle.py`. Then:
1. Add them under `si-release/` unchanged.
2. Verify the files against their checksum file, and confirm that `a77e5548…` is reproduced exactly as that release documents.
3. Rebuild `bundle.js` from them and confirm it is byte-identical to `si/worker/src/bundle.js`. Do not replace the bundle if it differs; document the difference instead.

If the original files cannot be recovered, do **not** reconstruct a "v1.1" from the bundle or from the v1 arrays and
present it as the original. A store rebuilt from the NASA files would be a new version with a new hash, and should
go through `HANDOFF.md` section 10.
